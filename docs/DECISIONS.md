# Решения

## Принятые — 02.10.2026, по итогам обсуждения с пользователем

- **D1. Расширение браузера, а не приложения под каждое устройство.** Настоящая страница провайдера, сайдбар внутри или рядом. Встраивание chatgpt.com/claude.ai в чужую страницу запрещено их заголовками (`X-Frame-Options`), поэтому обычная веб-страница не подходит; трансляция видео не даёт «настоящей страницы».
- **D2. Всё живёт на Mac.** Репозитории, план, сессии, пакет восстановления — в Project Web Pilot. Расширение — отображение и управление, без второй копии данных.
- **D3. Одна страница панели, три хозяина.** Боковая панель Chrome/Edge, боковая панель Firefox, iframe в странице для Safari и Firefox Android.
- **D4. Панель — страница расширения в отдельном origin.** Скрипты страницы провайдера не читают её содержимое (названия проектов, план).
- **D5. Сеть — только из фонового скрипта.** Фиксированные операции Host API, без произвольных URL. Контент-скрипт не делает запросов и не слушает `window.postMessage`. Сообщения принимаются только от своих контекстов расширения.
- **D6. Host API v1 живёт внутри Project Web Pilot.** Тот же store и проекция плана, что у сайдбара Electron. Явные идентификаторы в каждом запросе; выбор на устройстве не меняет выбор в окне Mac.
- **D7. Модель плана не меняется.** Один checkout = один current plan; расширение план только читает.
- **D8. Без разрушительных операций.** Удаление и архивирование проектов остаются в интерфейсе Web Pilot с подтверждением (контракт `PROJECT_ARCHIVE.md` Web Pilot).
- **D9. Без съёма ответов.** Адаптер: вставить, отправить, новый чат, открыть чат, наблюдать генерацию, адрес и заголовок. Никакого зеркалирования DOM и чтения ответов.
- **D10. Сначала ChatGPT, затем Claude.ai.** Для Claude.ai нужен публичный адрес MCP (Q6).
- **D11. Адаптеры ChatGPT — из Web Pilot.** На старте копирование при сборке с проверкой контрольной суммы, как staging WorkflowKit в Web Pilot. Общий пакет — позже (Q4).
- **D12. Сборка — свой скрипт без зависимостей** (`scripts/build.mjs`, решает Q2). Модули Web Pilot превращаются в один обычный скрипт: контент-скрипты не бывают модулями.
- **D13. В Safari фон — непостоянная страница, а не service worker.** На iOS service worker расширения может остановиться навсегда; непостоянная фоновая страница просыпается надёжно. В Chrome — service worker.
- **D14. Запасная отрисовка панели.** Если страница не даёт загрузить iframe расширения за 5 с, панель рисуется прямо на странице (теряется изоляция D4, поэтому это только запасной путь, R7).

## Принятые — 02.10.2026, после проверки в Safari на Mac

- **D15. Подписанная установка без режима разработчика.** Первая аудитория — автор и близкие. Mac: приложение-обёртка подписывается Developer ID, проходит нотаризацию Apple и раздаётся файлом .dmg, без App Store. iPad и iPhone: TestFlight. Chrome: Chrome Web Store с видимостью «по ссылке» (тот же архив — Edge Add-ons). Команда Apple — UkrHD (`LXY7H5ZUE9`), идентификатор `com.oleynik.WebPilotSidebar`. Проект Xcode хранится в репозитории (`apple/`), а не генерируется: обёртку придётся дорабатывать для подключения без кодов (Q8), поэтому упаковщик App Store Connect без Xcode не подходит. Подпись и загрузка — `scripts/release-apple.sh`, учётные данные остаются в Xcode.
- **D16. Две сборки: для разработки и рабочая.** `npm run build` → `dist/` с «Проверками этапа 0» (для временной установки в Safari 26+ и распакованной в Chrome); `npm run build:release` → `dist/release/` без тестовых действий, которые пишут в чат (их отклоняет и фоновый скрипт), и без надписей «этап 0». Подписанные версии и магазины — только рабочая сборка.
- **D17. Скрипты расширения — только ASCII.** Safari читает фоновые скрипты своей служебной страницы как Latin-1, и кириллица превращалась в крокозябры. Сборка заменяет не-ASCII символы на `\uXXXX`; смысл кода не меняется (проверено тестом).

## Открытые вопросы

- **Q1. Сетевой путь к Mac для устройств вне дома.** Варианты: WireGuard + свой VPS; Tailscale; Cloudflare Tunnel. Для этапа 0 — сам Mac (127.0.0.1) и временный HTTPS для iPad. Safari на iOS требует доверенного сертификата.
- **Q2. Сборка под браузеры.** Решено — D12.
- **Q3. Раскладка встроенной панели на iPad.** Сдвиг содержимого страницы или панель поверх. Решает этап 0.
- **Q4. Когда выносить адаптеры ChatGPT в общий пакет** для Web Pilot и расширения — после стабилизации второго потребителя.
- **Q5. Работа без запущенного Web Pilot** — требует выноса хоста в отдельную службу. Вне текущего объёма.
- **Q6. Claude.ai** — туннель OpenAI работает только с ChatGPT; нужен публичный MCP-адрес. Связано с Q1.
- **Q8. Подключение без кодов.** Цель — пользователь ставит расширение, принимает соглашение, и всё. Тот же Mac: native messaging — установщик Web Pilot регистрирует помощника, расширение получает у него токен (Safari — через нативную часть приложения-обёртки). iPad и iPhone: токен и адрес в связке ключей iCloud (один Apple ID = своё устройство) и постоянный адрес хоста вместо временного trycloudflare. Остальные устройства: QR-код или вход через аккаунт. Требует изменений в Web Pilot (этап 1 и дальше). Неустранимо: включение расширения и доступ к сайту в Safari, установка из магазина в Chrome.
- **Q9. Web Pilot как бэкенд без интерфейса.** Интерфейс — только в Web Pilot Sidebar; Web Pilot — служба с Host API, MCP и туннелем, на Mac или сервере. Главный вопрос — автоматика без открытой вкладки (автовыполнение, доставка без человека): нужен ли бэкенду свой скрытый браузер-исполнитель (связано с Q7). Также: место для установки и настроек, правило «кто отправляет» при нескольких устройствах, Android (в Chrome на Android расширений нет). Переход — постепенно, Electron-интерфейс убирать после паритета.
- **Q7. Host API при закрытом окне Web Pilot.** Сейчас закрытие окна завершает приложение. Варианты: фоновый режим (окно скрывается, приложение остаётся в строке меню и стартует при входе) или Host API отдельной постоянной службой рядом с MCP (связано с Q5). Минимальный вариант — фоновый режим.
