# Адаптер провайдера

## Контракт

Минимальный и одинаковый для всех провайдеров. Выполняется в контент-скрипте на странице провайдера.

| Операция | Результат |
| --- | --- |
| `inspect()` | `url`, `editorAvailable`, `writable`, `login`, `busy`, `experience` (Chat/Work) |
| `newChat(experience)` | Переход на новую страницу чата нужного режима |
| `open(chatUrl)` | Переход на сохранённый чат |
| `insert(text, requestId)` | Текст в поле ввода; повтор с тем же `requestId` не дублирует |
| `send(requestId)` | Отправка; `already-sent`, если сообщение с этим `requestId` уже есть |
| `observeRunning(callback)` | Начало и конец генерации по кнопке Stop; паузы до 5 с — одно задание |
| `conversationUrl()` | Адрес `/c/<id>` после первого сообщения |
| `title()` | Заголовок разговора — для синхронизации названий сессий |

Больше ничего: ни чтения ответов, ни API аккаунта, ни cookies.

Отказы — явные состояния для панели («нужен вход», «идёт генерация», «не найдено поле ввода»), без автоповторов в цикле.

## ChatGPT — первый провайдер

Переиспользуется из Project Web Pilot без переписывания:

- `src/chatgpt-dom.mjs` — селекторы и DOM-обёртка. Уже DOM-only и выполняется внутри страницы.
- `src/chatgpt-composer.mjs` — `pageOperation`: inspect, вставка, отправка, выбор Chat/Work, защита по `requestId`.
- `src/chatgpt-experience.mjs` — адреса Chat/Work и распознавание временных адресов разговора.
- `src/agent-timer.mjs` — правило паузы 5 с. В прототипе контент-скрипт применяет то же правило к кнопке Stop; сам класс `AgentTimer` остаётся в Web Pilot для учёта времени.
- `src/chatgpt-title.mjs` — при необходимости синхронизации заголовков.

В Web Pilot эти функции вызываются через `executeJavaScript` из основного процесса Electron. В расширении они выполняются прямо в контент-скрипте: `pageOperation` уже написана как самостоятельная функция страницы, меняется только способ вызова. Web Pilot экспортирует `pageOperation` ради Sidebar — ограничение записано в его `AGENTS.md`. Сборка проверяет, что на месте все экспорты, нужные расширению (`REQUIRED_EXPORTS` в `scripts/build.mjs`), иначе останавливается с понятной ошибкой.

Подключение кода — копирование при сборке с проверкой контрольной суммы (D11).

`ChatGPTComposer` используется без изменений. В Electron он вызывает `executeJavaScript(pageScript(args))`; в расширении этот вызов обслуживает контент-скрипт: аргументы восстанавливаются из точного формата `pageScript` и передаются в `pageOperation` напрямую — код не исполняется через eval. Если формат `pageScript` изменится, расширение остановится с ошибкой `ADAPTER_INCOMPATIBLE`, а не будет работать наугад.

Вставка: текущий Web Pilot вставляет пакет синтетическим событием paste (ProseMirror обрабатывает его одной транзакцией). Если редактор paste не принял (возможно в Safari), контент-скрипт вставляет текст прежним способом `execCommand('insertText')` — до этого в поле ничего не попало, поэтому повторной вставки нет. Если поведение из изолированного мира контент-скрипта всё же разойдётся с Electron — выполнение в основном мире страницы через `scripting.executeScript` с `world: "MAIN"` (проверка R1 этапа 0).

Известные отличия от десктопа: мобильная вёрстка chatgpt.com на iPhone может требовать дополнительных селекторов (R6 этапа 0).

## Хрупкость

Селекторы ломаются при смене вёрстки провайдера. Правило: только операции контракта, никакой косметики (цвета, автопрокрутка), чтобы поверхность поломок оставалась минимальной.
