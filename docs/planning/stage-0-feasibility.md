# Этап 0 — проверка осуществимости

## Результат

Ответ «да» или «нет» по главным рискам до любых изменений в Project Web Pilot. Прототип расширения работает с тестовыми данными и тестовым хостом.

## Что сделано

- **Расширение** (`extension/`, сборка `npm run build` → `dist/chrome`, `dist/safari`):
  - панель: проекты, сессии, текущий план с прогрессом, страница ChatGPT, индикатор агента, проверки этапа 0;
  - три хозяина панели: боковая панель Chrome, iframe на странице, встроенная отрисовка (запасной вариант, если страница блокирует iframe);
  - раскладки на странице: «сдвиг» и «поверх»; на узком экране панель свёрнута и открывается вкладкой WP;
  - новая сессия: создание на хосте → новый чат → вставка и отправка пакета → привязка `chatUrl`; открытие привязанной сессии.
- **Адаптер ChatGPT из Web Pilot** — `chatgpt-dom.mjs`, `chatgpt-composer.mjs`, `chatgpt-experience.mjs`, закреплены по SHA-256 в `vendor.lock.json`. Закреплена локальная версия Web Pilot `01da442`: она новее GitHub и вставляет пакет одним событием paste, как ProseMirror; если редактор paste не принял — прежним способом `execCommand`.
- **Тестовый хост** (`mock-host/`, `npm run host`) — контракт [host-api](../modules/host-api.md): сопряжение по коду, токены (хранятся только хеши), CORS только для расширений, план Project Web Pilot сам продвигается каждые 20 с.
- **Помощник установки для macOS** — `Web Pilot Sidebar.command` (ниже).
- **Проверки:** `npm test` — 19 тестов: хост, сборка и прогон помощника с поддельными инструментами macOS; `npm run e2e` — сквозной прогон Chrome-сборки на фикстуре страницы ChatGPT (нужен Playwright, см. начало `test/e2e/run.mjs`).

## Как проверить

### Самый простой путь — помощник

Двойной щелчок по **«Web Pilot Sidebar.command»** в корне проекта. Помощник:

- проверяет Node.js 22+ (если его нет — предлагает установить);
- находит Project Web Pilot рядом или просит указать папку;
- собирает расширение и запускает самопроверку;
- запускает тестовый хост в фоне;
- по выбору проводит через установку в Chrome, Safari на Mac (сам собирает приложение-обёртку в Xcode) и на iPad (скачивает cloudflared и поднимает временный HTTPS-адрес);
- копирует в буфер обмена путь, адрес и код подключения в нужный момент.

Повторный запуск того же файла — пульт: новый код подключения, HTTPS-адрес для iPad, остановка хоста. Ниже — те же шаги вручную.

### Подготовка

1. В папке проекта: `npm run build`. Сборка берёт адаптер из соседней папки `Project Web Pilot`. Если там код изменился относительно закреплённой версии, сборка остановится; после просмотра изменений — `npm run build -- --update-lock`.
2. Тестовый хост: `npm run host`. В терминале будет адрес `http://127.0.0.1:8787` и код подключения; новый код — Enter. Окно не закрывать.

### Chrome на Mac

1. `chrome://extensions` → «Режим разработчика» → «Загрузить распакованное» → папка `dist/chrome`.
2. Закрепить значок Web Pilot Sidebar. Чтобы панель была слева: настройки Chrome → «Внешний вид» → положение боковой панели → слева.
3. Открыть chatgpt.com и нажать значок — откроется боковая панель.
4. Подключить: адрес `http://127.0.0.1:8787`, код из терминала.
5. Пройти проверки из таблицы ниже.
6. Посмотреть, как будет в Safari: «Проверки этапа 0» → «Панель на странице: Показывать», затем переключать «Сдвигать страницу» / «Поверх страницы».

После правок кода: `npm run build`, кнопка обновления расширения в `chrome://extensions`, перезагрузка вкладки chatgpt.com.

### Safari на Mac

**Safari 26 и новее — без Xcode.** Safari → Settings → Developer → «Add Temporary Extension…» → папка `dist/safari`. Расширение появится в Settings → Extensions в разделе Temporary. После `npm run build` — кнопка Reload там же и перезагрузка вкладки chatgpt.com. При закрытии Safari расширение выгружается, его нужно добавить заново. В проверке 02.10.2026 Safari 27 счёл расширение из Xcode с подписью «для этого Mac» (ad-hoc) неподписанным и не показал его в списке.

**Подписанная версия** (рабочая сборка, D15): `npm run release:mac` → `.dmg` в `dist/release/`; приложение — в «Программы», запустить, «Закрыть и открыть настройки Safari», включить расширение. Меню «Разработка» не нужно.

После включения: на chatgpt.com разрешить расширению доступ к сайту, подключить — `http://127.0.0.1:8787` и код. Кнопка расширения на панели инструментов скрывает и показывает панель.

### Safari на iPad и iPhone

1. Временный HTTPS до тестового хоста — iPad не примет `http` и самоподписанный сертификат. Один раз `brew install cloudflared`, затем `cloudflared tunnel --url http://127.0.0.1:8787`. В выводе будет адрес `https://….trycloudflare.com`; он живёт, пока работает команда. Без кода подключения хост всё равно ничего не отдаст.
2. Установить через TestFlight: `npm run release:ios` загружает сборку в App Store Connect, приглашение приходит на почту Apple ID (D15).
3. На iPad: Настройки → Приложения → Safari → Расширения → Web Pilot Sidebar → включить, разрешить для chatgpt.com.
4. Открыть chatgpt.com в Safari. Панель появится слева; на iPhone она свёрнута и открывается вкладкой WP.
5. Подключить: адрес `https://….trycloudflare.com` и код из терминала.

## Ограничения прототипа

- Данные тестовые; Project Web Pilot не меняется.
- Индикатор агента отправляется на хост только для сессий, созданных или открытых из панели в этой вкладке.
- Временное расширение Safari (`dist/safari`) после `npm run build` обновляется кнопкой Reload в Settings → Extensions; подписанное — новым выпуском (`npm run release:mac`).
- `scripts/package-safari.sh` больше не нужен для установки: проект обёртки хранится в `apple/`. Скрипт оставлен, чтобы при необходимости заново сгенерировать проект из `dist/safari`.

## Границы

- Не менять Project Web Pilot, его службы, туннель и MCP.
- Только тестовые данные; реальные токены и адреса туннелей в репозиторий не попадают.
- Временный публичный адрес тестового хоста — только на время проверки.

## Условие остановки

Если R1 или R2 не решаются на iPad, расширение не даёт нужного результата. Тогда вернуться к выбору между Split View и тонкой оболочкой с двумя WebView.
