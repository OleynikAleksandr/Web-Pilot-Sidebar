# Краткая архитектура проекта

## Назначение

Сайдбар Project Web Pilot внутри настоящей страницы веб-чата провайдера в любом браузере. Всё проектное живёт на Mac в Project Web Pilot; расширение — тонкий слой отображения и управления. Продуктовый контракт — [PRODUCT](../PRODUCT.md).

## Устройство

```text
Браузер на любом устройстве
┌──────────────────────────────┐
│ Панель (страница расширения) │
│        ↕ сообщения           │
│ Фоновый скрипт ──────────────┼── HTTPS + токен ──┐
│        ↕ сообщения           │                   │
│ Контент-скрипт на chatgpt.com│                   ▼
│ (адаптер страницы)           │      Mac: Project Web Pilot
└──────────────┬───────────────┘      ├ Host API (новый)
               │ обычный вход         ├ проекты и сессии
               ▼                      ├ план (WorkflowKit)
          chatgpt.com ─── MCP ───────►└ MCP и туннель (как сейчас)
```

Части:

1. **Панель** — одна страница расширения `panel.html` в трёх хозяевах: боковая панель Chrome/Edge, боковая панель Firefox, iframe внутри страницы (Safari, Firefox Android). Это отдельный origin, скрипты chatgpt.com её содержимое не читают. Контракт — [panel](../modules/panel.md).
2. **Контент-скрипт** на странице провайдера: адаптер страницы, переиспользованный из Web Pilot, и раскладка встроенной панели. Контракт — [provider-adapter](../modules/provider-adapter.md).
3. **Фоновый скрипт** — единственный сетевой участник. Хранит токен устройства, выполняет фиксированный набор операций Host API, маршрутизирует сообщения между панелью и контент-скриптом.
4. **Host API** — новый модуль в Project Web Pilot на Mac. Использует тот же store сессий, проекцию плана и пакет восстановления, что и сайдбар Electron. Контракт — [host-api](../modules/host-api.md).

Агент по-прежнему работает с файлами через существующий MCP-коннектор ChatGPT. Расширение этот канал не трогает.

## Основные потоки

- **Новая сессия.** Панель → фон → `POST /v1/projects/{id}/sessions` → пакет и `requestId` → контент-скрипт открывает новый чат, вставляет пакет, отправляет → видит адрес `/c/…` → `PATCH /v1/sessions/{id}` с `chatUrl`. Сессия появляется и в Web Pilot на Mac.
- **Открыть сессию.** Панель → контент-скрипт переходит на сохранённый `chatUrl`.
- **Прогресс плана.** Видимая панель опрашивает план проекта; показывает ревизию и время последнего успешного чтения; при потере связи — «данные устарели», а не старый план как живой.
- **Агент работает.** Контент-скрипт наблюдает кнопку Stop → фон → панель и `POST /v1/sessions/{id}/agent-run` для таймера Web Pilot.

## Ключевые свойства

- Один экземпляр всего: репозитории, план, сессии — только на Mac.
- Выбор проекта и сессии на устройстве не меняет выбор в окне Web Pilot на Mac: все запросы содержат явные идентификаторы.
- Одна кодовая база расширения для всех браузеров; в Safari (Mac, iPad, iPhone) — в минимальном приложении-обёртке (`apple/`).

## Запуск и проверка

Для разработки: `npm run build` (расширение в `dist/chrome` и `dist/safari`), `npm run host` (тестовый хост), `npm test`. Рабочая сборка — `dist/release/`; подписанные выпуски: .dmg для Mac (Developer ID, нотаризация), TestFlight для iPad и iPhone, Chrome Web Store «по ссылке» (D15, D16).
